# AI Agent 工具安全控制 —— 项目架构汇报

> **题目 26：AI Agent 工具安全控制**
> 一句话定位：为「智能体可调用工具」建立一套**最小权限安全网关**，在智能体与实际执行之间插入强制校验层，使工具权限**可配置、可审计、可持久化**。

---

## 摘要

本项目的核心思路是 **「声明与实现分离」**：智能体（Agent Runtime）只读取工具的声明层（`SKILL.md`），真正的调用必须经由统一的安全网关（`cli.py + core/`），从而把权限校验从业务逻辑中剥离、集中到一处强制生效。

在此基础上，系统实现了三层能力：

1. **运行期强制闸门**——每一次工具调用都穿过「工具白名单 → 最小权限 → 危险确认 → 目录白名单 → 命令白名单」；
2. **配置期自然语言配置**——用 9 个安全配置工具，让用户以自然语言建立/修改安全边界，无需改代码；
3. **接入期评估引擎 + 分级确认环**——接入新工具时用 bandit / pip-audit 扫描，产出「建议分级及原因」回显；交互终端由用户确认/修改分级，非交互终端按建议直接准入。

## 1. 背景与问题

智能体可调用的工具数量与种类日益增多，但传统做法存在明显缺陷：

- 权限校验**硬编码在业务代码里**，分散、难维护；
- 缺少**配置入口**，用户无法在不改代码的前提下调整安全边界；
- 缺少**审计回溯**，无法回答「谁、何时、调用了什么、是否被拦截」。

因此需要一套独立于业务逻辑的安全控制层，统一接管智能体的工具调用。

---

## 2. 目标与方案

**目标**

- 建立最小权限机制（工具白名单、目录白名单、命令白名单、危险操作确认）；
- 让安全策略可配置、可持久化、可复用；
- 提供完整操作审计日志。

**方案**

- 声明与实现分离（`SKILL.md` 声明层 ↔ `cli.py/core` 实现层）；
- 运行期统一网关强制校验；
- 配置期通过自然语言交互生成/修改策略；
- 接入期用开源工具 bandit + pip-audit 自动评估风险分级。

---

## 3. 核心设计思想：声明与实现分离

这是整个架构的基石：

| 层次 | 载体 | 作用 |
|------|------|------|
| 声明层 | `SKILL.md` | 工具对外的「接口契约」，供 Agent Runtime 读取：描述功能、参数、风险 |
| 实现层 | `cli.py + core/ + external/` | 真正的安全网关与工具实现 |

Agent Runtime 只能读到声明，实际调用必须经过网关。由此实现两个关键效果：

- **权限校验集中化**——所有工具的调用都走同一条安全链路；
- **入口唯一化**——原工具实现被收编进 `external/`，仅保留声明 `SKILL.md` 作为唯一入口，避免绕过网关。

## 4. 总体架构

```
┌─────────────────────────────────────────────────────┐
│  配置期：自然语言配置安全策略（9 个配置工具）            │
│  import_tool / confirm_tool_risk / set_* / add_* ...  │
└───────────────────────┬─────────────────────────────┘
                        │ 写入 Policy（持久化到 policy.json）
┌───────────────────────▼─────────────────────────────┐
│  接入期：评估引擎（bandit + pip-audit）                 │
│  扫描源码危险模式 / 依赖 CVE → 建议分级 + 可读原因        │
└───────────────────────┬─────────────────────────────┘
                        │ 作为接入与分级的依据
┌───────────────────────▼─────────────────────────────┐
│  运行期：每次调用强制过闸门                              │
│  工具白名单 → 最小权限 → 确认 → 目录白名单 → 命令白名单   │
└─────────────────────────────────────────────────────┘
```

**核心模块分工（`core/`）**

| 模块 | 职责 |
|------|------|
| `security.py` | 风险等级（low/medium/high）、工具元数据、结果、异常 |
| `registry.py` | 工具白名单登记处 + 最小权限门控 |
| `gateway.py` | 运行期安全网关（核心闸门） |
| `tools.py` | 内置工具实现 + 命令白名单 |
| `directory_policy.py` | 目录白名单（路径越界校验） |
| `guard.py` | 危险操作确认 |
| `audit.py` | 审计日志（JSON Lines 落盘） |
| `policy_store.py` | 策略持久化 + 休眠/激活状态 |
| `assessor.py` | bandit + pip-audit 评估引擎 + 分级原因生成 |
| `importer.py` | 工具接入器（复制/声明/评估/注册） |
| `external_tools.py` | 外部工具 subprocess 执行 + 注册记录持久化 |
| `config_tools.py` | 9 个安全配置工具 + 分级确认环 |
| `agent.py` / `llm_router.py` | 意图路由（关键词 / DeepSeek LLM） |

## 5. 运行期安全：闸门体系

每次工具调用按顺序穿过以下闸门：

| 闸门 | 名称 | 作用 |
|------|------|------|
| 1 | 工具白名单 | 未注册工具一律拦截 |
| 1.2 | 策略禁用 | 被策略显式禁用（`allowed=false`）的工具拦截 |
| 1.3 | 默认拒绝 | 外部工具 deny-by-default，未准入（`allowed=false`）拦截 |
| 1.5 | 任务最小权限集 | 会话级任务范围约束 |
| 2 | 最小权限 | 工具风险等级不得超过会话 `max_risk` 上限 |
| 3 | 危险操作确认 | 中/高风险操作需用户确认，拒绝则终止 |
| 4 | 目录白名单 | 越界路径拦截（仅内置工具生效） |
| 5 | 命令白名单 | 越权命令拦截（仅内置工具生效） |

---

## 6. 白名单分层：内置工具 vs 外部工具

| 白名单 | 内置 func 工具（进程内执行） | 外部 subprocess 工具（`external/` 收编） |
|--------|------------------------------|------------------------------------------|
| 工具白名单 | 生效 | 生效 |
| 目录白名单 | 生效 | 不生效（进程边界） |
| 命令白名单 | 生效 | 不生效（进程边界） |

外部工具因独立进程边界，网关只能管控「是否启动 + 传入参数」，无法约束其内部访问的目录与执行的命令。因此，其内部危险进程/命令改由 **bandit 在接入时静态扫描**发现，并作为风险分级依据。

## 7. 配置期：自然语言配置安全策略

提供 9 个安全配置工具，用户可用自然语言完成安全边界的建立与调整：

| 配置工具 | 作用 |
|----------|------|
| `configure_tools` | 多轮确认向导，引导式配置 |
| `import_tool` | 接入外部 Skill + Script 项目（复制/声明/评估/注册），交互确认或非交互按建议直接准入 |
| `confirm_tool_risk` | 分级确认：确认或修改评估风险并显式准入 |
| `assess_tool` | 评估第三方工具（bandit 划风险 + pip-audit 判准入） |
| `assess_builtin_tools` | 用 bandit 自检内置工具风险等级 |
| `set_tool_policy` | 手动设置某工具是否允许及其风险等级 |
| `set_max_risk` | 设置会话风险上限 |
| `add_directory_whitelist` | 添加目录白名单 |
| `add_command_whitelist` | 添加命令白名单 |

意图路由支持两条链路：默认**关键词规则**（离线、零依赖），配置 DeepSeek 后切换为**真实 LLM 意图路由**（LLM 只负责「选工具 + 抽参数」，执行仍受全部闸门约束）。

## 8. 评估引擎与分级确认环

这是本项目在「接入新工具」场景下的特色闭环：

```
扫描 → 建议分级及原因 → 回显 → 用户确认分级 → 准入
```

1. **扫描**：bandit 扫源码危险模式（`shell=True`、`subprocess`、硬编码密钥等），pip-audit 扫 `requirements.txt` 已知 CVE；
2. **建议分级**：`risk = max(基础风险, bandit 命中风险)`，bandit 只上调、不降级；
3. **原因回显**：把命中项翻译为可读中文（含文件:行号与严重度），随接入结果返回；
4. **用户确认**：在 `import_tool` 内一步完成——**可交互终端**询问「按建议分级准入或输入 low/medium/high 修改」，确认后写入 `allowed=true`；**非交互终端**（子进程 / nanobot `--tool` 结构化调用）直接按建议分级准入。`confirm_tool_risk` 仍可用于接入后再调整分级。

示例回显（交互终端）：

```
[工具接入] mytool 扫描完成，建议风险等级：high
分级依据：
  - subprocess 使用 shell=True（命令注入风险）（cli.py:12，severity=HIGH）
  - 依赖 demo 1.0 存在已知漏洞 PYSEC-1（修复版本：1.1）
是否按建议分级 'high' 准入？[y/回车=确认] 或输入新等级 low/medium/high y
```

## 9. 休眠 / 激活机制

- 安全控制默认处于**休眠态**（`policy.enabled=false`）：业务工具旁路执行，只审计、不拦截，便于先完成工具接入与策略配置；
- 首次成功执行任一**配置工具**后，安全控制自动**激活**（`enabled=true`）并持久化到 `config/policy.json`；
- 激活后，业务工具每次调用都穿过全部运行期闸门。

---

## 10. 元级安全边界

这是整套系统「防智能体自越权」的关键设计：

- 配置工具**强制用户确认**，`auto_approve` 对配置操作不生效；
- 智能体可以「建议」权限，但**落盘生效必须经过用户确认**；
- 审计日志**只记参数键名、不记参数值**，防止敏感数据泄漏；
- 评估结果只作建议，**最终准入与分级由用户决定**。

---

## 11. 关键结论

1. 通过「声明与实现分离」，把权限校验集中到统一网关，实现入口唯一、无法绕过；
2. 通过「运行期闸门 + 白名单分层」，实现最小权限的强制约束；
3. 通过「bandit + pip-audit 评估 + 分级确认环」，把工具接入从「人工判断」升级为「扫描建议 + 用户确认」；
4. 通过「休眠/激活 + 强制确认 + 审计脱敏」，守住「谁有权改权限」这一元级安全边界。

整套系统核心网关仅依赖 Python 标准库即可运行，bandit / pip-audit 作为评估引擎按 `requirements.txt` 安装，具备良好的可移植性与可复现性。
